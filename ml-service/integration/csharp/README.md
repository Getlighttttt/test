# Интеграция главного бэкенда (WmsApi, C#) с ML-сервисом

Для новой версии проекта (линии L1/L2, контейнер `app` на 8080, ML на 8001). ~5 минут.

## 1. Скопировать два файла
- `Controllers/MlController.cs` → `backend/WmsApi/WmsApi/Controllers/`
- `Models/MlDtos.cs` → `backend/WmsApi/WmsApi/Models/`

`MlController` принимает тревоги ML, создаёт `Alert` и `ReplenishmentRequest` (`AutoGenerated = true`)
только для линий L1/L2 (через `ProductionLines.Normalize`), пишет `ML_ALERT` в MovementLogs
и проксирует кнопки диспетчера в ML. Собран и проверен с моделями новой версии (.NET 8).

## 2. `Program.cs` — HttpClient для ML (перед `var app = builder.Build();`)
```csharp
builder.Services.AddHttpClient("ml", c =>
{
    // В Docker: ML_SERVICE_URL=http://ml-service:8000 (уже задан в docker-compose.yml)
    c.BaseAddress = new Uri(builder.Configuration["ML_SERVICE_URL"]
                            ?? builder.Configuration["Ml:BaseUrl"]
                            ?? "http://localhost:8000");
    c.DefaultRequestHeaders.Add("X-API-Key", builder.Configuration["Ml:ApiKey"] ?? "dev-ml-key");
    c.Timeout = TimeSpan.FromSeconds(10);
});
```

## 3. `appsettings.json` — по желанию
```json
"Ml": {
  "BaseUrl": "http://localhost:8000",
  "ApiKey": "dev-ml-key"
}
```
Без этой секции работают значения по умолчанию (`localhost:8000`, ключ `dev-ml-key`).

## 4. (Рекомендуется) надёжное создание таблиц DB2

`db2.Database.EnsureCreated()` создаёт таблицы, только если в DB2 нет **ни одной** таблицы.
ML-сервис тоже хранит в DB2 свои таблицы. ML при старте ждёт, пока C# создаст свои
(до 90–120 с), поэтому при обычном запуске всё работает. Но если ML запустить на пустой
DB2 надолго раньше C#, `EnsureCreated()` пропустит создание `MovementLogs`,
`LineConsumptionLogs`, `PredictionHistories`. Чтобы порядок запуска не имел значения,
замени в `Program.cs` строку `db2.Database.EnsureCreated();` на:

```csharp
// DB2 shared with the ML service: create our tables when "MovementLogs" is missing,
// even if the ML service has already created its own tables.
var db2Creator = db2.Database.GetService<IRelationalDatabaseCreator>();
if (!db2Creator.Exists())
    db2Creator.Create();
var hasMovementLogs = db2.Database.SqlQueryRaw<int>(
        "SELECT COUNT(*)::int AS \"Value\" FROM information_schema.tables WHERE table_name = 'MovementLogs'")
    .AsEnumerable().First() > 0;
if (!hasMovementLogs)
    db2Creator.CreateTables();
```
и добавь вверху `using Microsoft.EntityFrameworkCore.Infrastructure;` и
`using Microsoft.EntityFrameworkCore.Storage;`.
(Этот кусок использует стандартный API EF Core 8; собрать его без NuGet у меня не было возможности —
проверьте сборку в Visual Studio.)

## Проверка
1. Запустить WmsApi и ML (`uvicorn app.main:app --port 8000`).
2. В Swagger ML (`http://localhost:8000/docs`) — `POST /api/telemetry`, заголовок `X-API-Key: dev-ml-key`:
   ```json
   {"lineName": "L1", "productCode": "MAT-001", "currentStock": 5, "consumptionRate": 130, "plannedRate": 130}
   ```
3. В DB1 появятся `Alert` и `ReplenishmentRequest` с `AutoGenerated = true` для L1/MAT-001,
   а складник увидит заявку в TSD.
